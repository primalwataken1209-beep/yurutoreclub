【1. 「確認中…」のまま止まるバグの原因と修正】
============================================================

■ 根本原因（2つありました）

原因①：画面切り替えの判定順序のバグ【これが主原因】
  最初のログイン/登録画面（WelcomeGate）から新規登録した場合、
  確認メール待ちの状態には正しくなっていたのに、
  画面の表示判定が「WelcomeGate → 確認メール画面」の順だったため、
  確認メール画面に切り替わらず、WelcomeGateが表示され続けていました。
  → 見た目上「確認中…のまま止まった」ように見えていました。
  → 判定順序を入れ替え、「確認メール待ち」を最優先で表示するよう修正。
     どの画面から登録しても、必ず確認メール画面へ切り替わります。

原因②：例外発生時にローディングが解除されない構造
  通信エラーなどで例外が投げられた場合、setAuthLoading(false) に
  到達せず「確認中…」が残る構造でした。
  → 全ての認証処理（ログイン／新規登録／再送信／パスワード再設定／
     Googleログイン）を try / catch / finally 構造に書き換え。
     成功・失敗・例外のどの場合でも finally で必ずローディングを解除します。

■ 合わせて実装したこと

・登録ボタンの連打防止（二重実行防止）
  authBusyRef という即時ガードを追加。処理中に再度押されても
  2回目以降は何もせずに無視します。ボタン自体も処理中はdisabledです。
  （画面表示用のauthLoadingとは別に用意した理由：Reactのstate更新は
    一瞬遅れるため、連打の「瞬間」はstateだけでは防げないからです）

・成功時の表示
  「確認メールを送信しました。メール内のリンクを開いて登録を完了して
  ください」という確認待ち専用画面（ConfirmEmailScreen）へ切り替わります。
  再送信ボタン・ログイン画面へ戻るボタン付き。

・確認メールのリンクから戻るURL
  signUp に emailRedirectTo を追加し、「今アプリを開いているURL」
  （本番: https://unique-parfait-888fbc.netlify.app/）へ戻るよう明示しました。
  ※Supabase管理画面の Authentication → URL Configuration →
    Redirect URLs に https://unique-parfait-888fbc.netlify.app/** が
    登録されていることを確認してください（未登録だと戻れません）。

・古い認証コードの削除
  どこからも呼ばれていない未使用のLoginScreenコンポーネント
  （死にコード）を削除しました。実際に使われている認証画面は
  WelcomeGate（初回ゲート）とRegisterScreen（オンボーディング内）の
  2つで、認証処理自体はAppLogic内のhandleLogin/handleRegisterに
  一本化されています（画面は2つでも処理は1つです）。

【2. Android・iPhone表示の切り替え】
============================================================

■ 原因
  このアプリは開発初期の「デバイスプレビュー」として、
  iOS用フレームとAndroid用フレームを常に2つ並べて描画する
  作りになっていました。PCでは横並び表示ですが、画面幅の狭い
  スマホでは縦に2つ積まれて表示されていました。

■ 修正内容
  OS自動判定関数 getDeviceOS() を追加しました。
  ・navigator.userAgent / navigator.platform / maxTouchPoints で判定
  ・画面幅では判定していません（OS判定とレスポンシブは別）
  ・iPadOSがMacを名乗るケースにも対応
    （platform === 'MacIntel' かつ maxTouchPoints > 1 → iOS扱い）

  Reactの条件分岐で、該当OSの画面「だけ」を描画します
  （CSSで隠すのではなく、不要な方はそもそも描画されません）。

  ・Android端末 → Android専用画面のみ描画
  ・iOS端末（iPhone/iPad/iPod） → iOS専用画面のみ描画
  ・PC（Windows/Mac等） → 従来どおりのデバイスプレビュー
    （2台並び表示。既存デザインそのまま）

■ 実機での見た目調整（real-device CSS）
  実機表示のときだけ、開発用の「フェイク端末枠」
  （黒い縁・偽ノッチ・偽カメラ・偽ナビボタン）を非表示にし、
  画面いっぱいにアプリを表示するCSSを追加しました。
  PCプレビューの見た目には一切影響しません。

【今後の改善案】
============================================================
1. PC表示は現在「開発用プレビュー（2台並び）」です。β公開時には
   PC向けに1画面のセンター表示へ切り替えることを検討してください。
2. app.js / script.jsx / inline.jsx（未使用の古いコピー）は
   次回リリース前に削除して混乱を防ぐことをおすすめします。
3. 確認メール完了後に自動でログイン状態を検知して画面を進める
   （onAuthStateChangeでの自動遷移強化）とさらに親切です。
4. Netlifyへのデプロイを本番/プレビューで分け、プレビューURLも
   SupabaseのRedirect URLsに登録しておくとテストが楽になります。
5. 実機のノッチ/セーフエリア対応（viewport-fit=cover）は
   PWA化する際に合わせて調整するのがおすすめです。
