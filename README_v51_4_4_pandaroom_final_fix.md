## 3. Lv.6 になっていた原因（2つ重なっていた）
**原因1: 部屋の解放記録が「guest共通キー」に残り続けていた（Lv.6 16/35 の主因）**
- 体験版の部屋の解放記録 `yurutore_room_seen_unlocks_v1_guest`（一度解放した家具＝everOk）と、パンダ統計 `yurutore_panda_stats_v1_guest`（来室回数・会話日数）は、体験版ユーザー全員で共通の `guest` キーに保存されます。
- ログアウトすると体験版の記録（state）は初期化されますが、この2キーは消えません。
- そのため、同じ端末で体験版を新しく始めると、記録0件・プロフィール0回なのに、前回の体験版で解放した家具がそのまま「解放済み」として数えられていました。
- 実ブラウザで再現済み: 体験版で3件記録（Lv.4 7/35）→ ログアウト → 新しく体験版を開始 → 記録0件なのに **Lv.4 7/35**。前回解放16点の状態を置いた場合は **Lv.6 17/35** になる（修正前ビルド）。
- デモ用固定値や架空データは原因ではありませんでした（state の初期値 `DEF` は全て0／空）。

**原因2: 基本3点がレベル計算に含まれていた**
- ラグ・ローテーブル・座布団の3点は最初から解放済み（`always:true`）で、解放数 n に必ず含まれます。
- `roomLevelOf` は `n<=2` で Lv.1 だったため、まっさらな新規ユーザーでも n=3 → **Lv.2 3/35** から始まっていました（v30で基本3点を足したときにLv.1の閾値が合わなくなったもの）。

## 4. Lv.1 開始をどう実現したか
- 表示文字列の固定はしていません。レベルは従来どおり `roomLevelOf(解放数)` で計算しています。
- 原因2の対策: 基本3点だけの状態（n=3＝実績0件）を Lv.1 と判定。n≥4 の判定は従来と1件も変わりません。
  - 解放数→レベル（修正後）: 0〜3→1 / 4→2 / 5〜6→3 / 7〜8→4 / 9〜10→5 / 11以上→6
  - 修正前との違いは n=3 の1点のみ（2→1）
- 原因1の対策: 体験版の初期設定完了時に、guest の state が完全に空（記録・ミッション・ポイント・会話・タイムカプセルがすべて0件）の場合に限り、上記 guest キー2つだけを削除します。
- 進捗表示: 新規は **Lv.1 3/35**。3は部屋に最初から置かれている基本3点で、内部の解放状態と完全に一致しています（画面だけLv.1・内部はLv.6相当、という状態はありません）。

## 5. 既存ユーザーへの影響
- ログイン済みユーザー: キーは `…_{ユーザーID}` で別管理のため、Bの削除処理は一切触れません。保存データも変更しません。
- 実績1件以上のユーザー: レベル判定は修正前と同一（変化なし）。
- 実績0件のユーザー: 表示が Lv.2 → Lv.1 に変わるだけ（レベルは保存されておらず、表示のみ。他の機能はレベルを参照していません）。
- 体験版を継続中のユーザー: 初期設定をやり直さない限りBは呼ばれません。また state に何か1件でもあれば何もしないため、記録は守られます。
- レベルアップ条件・家具の解放条件は変更していません。

## 9. 見つけたが修正していない点（報告のみ）

3. **使われていない旧カード**: ホームの「装飾ありのひとことカード」（`HOME_SHOW.daily365Rich=false` で非表示）の中に日数表示が残っています。フラグを戻さない限り表示されません。
4. **PCのデバイスプレビュー**: iOS枠とAndroid枠は記録を別々に持ちますが、部屋の guest キーは共通です（PCプレビューでのみ起こり、スマホ実機には関係ありません）。
5. **冬限定の家具**: 12〜2月は、部屋に1回入るとブランケットが解放される仕様のため、記録0件でも初回入室後に Lv.2 4/35 になります（解放条件どおりの動作）。
