# ゆるトレ倶楽部 v42.2 — パンジロー ミニアクション

ベース：`yurutore_v42_1_living_assets_clean`

パンジローを**常時動かすのはやめました。**
基本は完全に静止して生活していて、ときどき短い仕草をして、また静止へ戻ります。

> 部屋を開いた瞬間は普通に生活している。
> 少し眺めていると「今ちょっと動いた！」と気づく。
> さらに見ていると「また何かするかな？」と思える。

---

## 1. いちばん大事な変更：常時ループを全廃した

v42／v42.1 では、ポーズごとに**無限ループのCSSアニメーション**が回っていました。

| 廃止したもの | 中身 |
|---|---|
| `.act-normal` | 5秒周期の呼吸を無限ループ |
| `.act-window` | 22秒周期の首かしげを無限ループ |
| `.act-eat` | 9秒周期の食べる動きを無限ループ |
| `.act-relax` | 6秒周期の寝息を無限ループ |
| `.act-workout` | 14秒周期の筋トレを無限ループ |
| `.act-sofa` | 6秒周期の呼吸を無限ループ |
| `.anim-blink42` | 9秒周期のまばたきを無限ループ |
| `PANDA42_ACTIONS` の `anim` フィールド | 上を割り当てるための項目 |

**いまは「CSSクラスが付いていない＝完全に静止」が基本の状態です。**
JS側のタイマーが一定間隔で「1回だけ再生されるクラス」を短時間つけ、終わったら外します。
`animation` はすべて再生回数 `1`（`infinite` は1つも使っていません）。

禁止事項はすべて満たしています。

| 禁止 | 状態 |
|---|---|
| 常時左右に揺れる | なし（横移動は window の `mini-lean` のみ、2.6px・2.8秒で戻る） |
| 常時上下に動く | なし（上下は ramen / workout の仕草中のみ、最大 1.1px） |
| 常時回転する | なし |
| 常時ズームする | なし（拡大は仕草中のみ、最大 101.8%） |
| 背景が動く | なし（窓の景色・カーテン・家具には一切触れていません） |
| 派手なパーティクル | なし（小さな文字が1個、低確率で出るだけ） |
| キャラ全体がずっとフワフワ | なし（静止時の位置ズレ実測 0.00px） |
| すべて同じアニメーション | なし（ポーズごとに別の仕草・別の間隔） |

### 小さな文字について

「ズズ…」「ふぅ〜」「ぷは〜」は、既存の『今日のひとり言』と同じやさしいチップ（生成り色の角丸）で表示します。
絵文字（🍕 💦）と寝息の `Z z` はチップを付けず、そのまま小さく出します。
どれも**1個だけ**、ふわっと上に浮いて消えます。パーティクルは使っていません。
JS側のタイマーが必ずDOMから削除するので、画面に残り続けることはありません。

## 4. タイマー実装方式

指示どおり **`setInterval` は使わず、`setTimeout` → 実行 → 次の `setTimeout` の連鎖方式**です。

```
待つ(setTimeout) → 仕草クラスを付ける → 仕草の時間だけ待つ(setTimeout)
→ クラスを外して静止へ戻す → また待つ …
```

安全対策：

- タイマーIDは常に**1本だけ**（`timerRef`）。張り替える前に必ず `clearTimeout` する
- `alive` フラグを持ち、アンマウント後に発火したコールバックは何もしない
- `pose` / `enabled` が変わったら作り直す（前のタイマーは必ず停止）
- `useEffect` のクリーンアップで確実に停止 → **多重 `setTimeout` もメモリリークも発生しない**

### 停止条件（パンダルーム以外では1本も動かない）

タイマーが動くのは、次を**すべて**満たすときだけです。

1. v42の生活画像が表示されている（`poseImgOk`）
2. アプリの「動きを減らす」設定がオフ（`rs.motion`）
3. 端末の `prefers-reduced-motion` が `reduce` でない
4. パンダルームが実際に画面に出ている
   - タブが非表示になったら停止（`visibilitychange`）
   - スクロールで画面外に出たら停止（`IntersectionObserver`）
   - **全画面パンダルームを開いているあいだ、裏のホーム側は停止**（`paused` プロップ）
5. パンダルームを離れたらコンポーネントごとアンマウント → 停止。再入室で再初期化

### 実測（`setTimeout` / `setInterval` をラップして生存数を計測）

```
起動4秒後       : setTimeout生存=7  / setInterval生存=2   ← 起動時の一時的なもの
さらに7秒後     : setTimeout生存=2                        ← 2フレーム分。増えていない＝多重なし
タブを非表示に  : setTimeout生存=0                        ← ミニアクションのタイマー完全停止
非表示のまま6秒 : setTimeout生存=0
タブを再表示    : setTimeout生存=2                        ← 自動で再開
「みんな」へ移動: パンダルームDOM消滅=true / 生存=1        ← iOS側が停止（残り1本はAndroid枠）
移動後8秒       : 生存=1                                   ← 増えていない＝リークなし
```

全画面を開いたときのデバッグ表示：

```
["mini: 停止(motion/画面外) [?mini=1]",   ← 裏のホーム側は停止
 "mini: 静止中 [?mini=1]"]                ← 全画面側だけ動く
```

`setInterval` の2本は既存の時計（`PandaRoom` の時刻更新）で、ミニアクションでは **0本**です。

## 5. タップ競合対策

**タップリアクションを常に優先します。**

1. `onPandaTap` の先頭で `interruptMini()` を呼び、進行中の仕草をその場で止めて静止へ戻す
2. 同時に、次の発火を通常の間隔（8〜30秒）から仕切り直す
3. 描画側でも二重に保証：タップ演出中は**そもそもミニアクションのクラスを付けない**

```js
const tapping = !!(fxKey && rs.motion);
const bodyCls = tapping ? 'mini-tap' : (miniAct ? miniAct.cls : '');
```

これにより、`transform` を2つのアニメーションが奪い合うことがありません。
小さな文字（fx）もタップ中は表示しません。

既存の `onPandaTap` / `panda_tap` 計測 / 💕🎵✨ の演出 / 会話は**すべて維持**しています。

実測（`workout` の仕草の最中にタップ）：

```
タップ直後: {"cls":"mini-tap", "fx":false, "anim":"pjMiniTap", "speech":true}
→ 自動ミニアクションが消え、タップ反応と会話だけになる：OK
```

## 6. reduced-motion 対応

既存の `@media (prefers-reduced-motion: reduce)` を維持したうえで、**二重に**停止します。

1. **JS側**：`prefersReducedMotion()` が true ならタイマーを1本も起動しない
   （＝クラスも付かず、小さな文字も生成されない）
2. **CSS側**：万一クラスが付いても `animation: none !important`。
   `.pj-mini-fx` は `opacity: 0 !important` も併記

**生活画像そのものは通常どおり表示されます。**

実測（`reducedMotion: 'reduce'` で12秒観察）：

```
ミニアクションのクラスが付いた : いいえ(OK)
小さな文字(fx)が出た           : いいえ(OK)
生活画像                       : panda42_workout.webp / animationName=none
debug                          : mini: 停止(motion/画面外)
```

アプリ内の「動きを減らす」設定（`rs.motion`）でも同じく停止します。

## 7. `?mini=1` の使い方（開発用）

既存の `?debug=1` / `?hour=` / `?action=` / `?variant=` はそのまま維持。追加で：

```
?mini=1
```

を付けると、確認用に2つの挙動が変わります。

1. **待ち時間を 0.8〜2.4秒に短縮**（通常は8〜30秒）
2. **候補を順番に再生**（通常は重み付きランダム）。少し待てば全部の仕草を確認できます
3. 小さな文字（fx）を毎回表示（通常は22〜35%の確率）

使用例：

```
?debug=1&action=workout&mini=1              → 数秒以内に筋トレの仕草を確認できる
?debug=1&action=sofa&variant=beer&mini=1    → ジョッキを持ち上げる仕草を確認できる
?debug=1&action=eat&variant=pizza&mini=1    → 「もぐ」＋🍕 を確認できる
?debug=1&action=relax_floor&mini=1          → 呼吸と Z z を確認できる
```

**本番UIには一切表示されません**（URLに付けたときだけ有効）。

`?debug=1` の自己診断パネルに1行追加しました。

```
mini: reps +💦 [?mini=1]        ← いま出ている仕草と文字
mini: 静止中 [?mini=1]           ← 待機中
mini: 停止(motion/画面外)        ← タイマーが動いていない
```
