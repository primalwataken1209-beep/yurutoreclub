# 本番非接続の実ブラウザ検証

既存の26件に加え、Chromiumで画面の表示と体験版を検証します。追加Secretsは不要です。

Chromium自身のsandboxも有効にし、公式Playwright v1.64.0のseccomp_profile.json（Git blob `fddc05fb520affb145404e6f6f647ca96af8087d`）を同梱して使用します。ホストの権限やシステム設定は変更しません。

## 検証対象

- デスクトップで1画面だけ表示されること、日英切替
- 新規体験版の設定からホームまで進むこと
- 初期パンダルームがLv.1・3/35であること、全画面の開閉、再読み込み後の体験版維持
- Android相当の390×844画面で1画面表示、横方向のはみ出しがないこと
- プライバシーポリシーが表示されること
- JavaScript実行エラー、CSP違反、外部リクエストがないこと

画像はwelcome-ja / guest-home / guest-room / mobile-welcome / final-stateのJPEGとしてActions artifactへ保存します。存在しないローカル画像があれば、TAPのBROWSER_MISSINGに一覧を記録します。

## 隔離と実環境との差

承認済みのテストと実行役を使い、PRのindex.htmlをそのままブラウザ内Babelで変換して実行します。React/ReactDOMは本体と同じ18.3.1、Babel standaloneは7.24.7です。CDN参照だけをコンテナ内ローカル配信へ置換し、Supabase SDKは読み込まずnullクライアントとして動かします。

PR版の_headersにCSPがあればそれを適用し、まだCSP未導入のときだけPR #2（2586c70）の定義を検証用サーバーで適用します。承認済み_headersにCSPがあるのにPRが削除していたら失敗します。さらに外部通信を禁止する別のCSPを重ねます。コンテナもnetwork none、ブラウザ側も外部リクエストを遮断します。ローカルの体験版データだけを使い、実アカウントは作りません。

この確認は本番でのCDN接続、メール/Google認証、Supabaseへの投稿や写真アップロード、署名URL、退会の実サービス連携を検証するものではありません。それらには別のテストSupabaseと認証設定が必要です。本番A/Bアカウントでの書き込みテストはしません。

## 結果の扱い

スクリーンショットはサンドボックスの標準出力でデータとして送り、承認済みの取り出し処理がファイル名・JPEG形式・2 MiB上限を検証して、新規のrunner-tempへ保存します。コンテナへホストのレポート保存先をマウントしません。既存の10 MiBログ上限も維持します。

通常PRではbase/default側の承認済みテストを使います。テスト追加自体は作業ブランチのbootstrap経路で確認し、レビュー後に必須セットへ取り込みます。mainや本番への適用は別途明示承認が必要です。
