## P1-1 非公開アカウントの投稿の保護（SQL・未適用）
- 原因：リポジトリ上の posts の SELECT ポリシーは v43 の `"posts: read alive"`（`is_deleted = false or user_id = auth.uid()`）のみで、投稿者の公開/非公開を見ていない。コメント・リアクション（v51.4.1）の保護は posts の RLS に依存している。アプリ側でも `is_public` の絞り込みは無い。
- 本番の posts ポリシーは未確認のため、**現在の本番の安全性は断定できません**。
- 修正：新しい migration で `"posts: read own or public"` を定義（自分の投稿は削除済みも含めて閲覧可／他人は「削除されていない かつ 投稿者が公開」のみ）。他テーブル・INSERT/UPDATE/DELETE は無変更。
- 安全装置：1トランザクション。想定外の SELECT/ALL ポリシーが posts に残っていれば例外で全体ロールバック（DB無変更）。
- 適用手順（**健太郎さんの確認後に手動で**）：① `v51_4_6_verify_readonly.sql` を実行し結果を保存・共有 → ② 内容確認後に migration を SQL Editor で実行 → ③ verify を再実行。戻す場合は rollback（適用前の本番定義が v43 と違う場合は①の結果をもとに戻す）。

## P1-2 退会時の Storage 一覧取得エラー
- 原因：post-images の `list` エラーを内容に関係なく「バケット未作成」とみなしてスキップしていたため、一時的な障害・権限エラーでも退会が成功扱いになり、写真が残る（再試行不可）。avatars も同じ作り。
- 修正：エラーメッセージが「Bucket not found」の場合のみスキップ。それ以外は失敗として返す（Auth ユーザーは削除されないため利用者は再試行できる）。avatars にも同じ修正を適用（承認済み）。
- 本番反映：マージ後に `supabase functions deploy delete-account` が必要（健太郎さんの作業）。

## P2 SNS投稿削除時の写真削除失敗
- 原因：投稿を削除済み（image_path=null）にした後で写真を削除し、写真削除の失敗を無視していた → 参照されない写真がサーバーに残り、再試行手段が無い。プライバシーポリシーの「投稿を削除すると写真も削除」と不一致。
- 修正：順番を「写真削除 → 投稿の削除」に変更。写真削除に失敗したら投稿はそのままでエラー表示（既存文言「削除できなかったみたい🐼」）。写真削除後に投稿更新が失敗しても投稿が残るので同じ操作で再試行可。プライバシーポリシーの文言は変更なし。

## テスト結果
1. **SQL（ローカルPostgreSQL 16＋Supabase相当のスタブ、既存migrationを順に適用）**
   - 修正前（v43ポリシー）：他人Cから非公開Bの投稿・コメント・リアクションが見え、Bの非公開投稿へのコメント挿入も成功 ＝ 指摘を再現
   - 修正後：Cから見えるのはA公開の投稿だけ（Bの投稿・コメント・リアクション0）、Bの非公開投稿へのコメント挿入はRLSで拒否、A公開投稿へのコメントは可
   - B本人：自分の非公開投稿・削除済み投稿・自分の写真が見え、ソフトデリートも可
   - 写真（post-images）の閲覧範囲は修正前後とも変化なし（v51.2のStorageポリシーで既に公開者のみ）
   - 循環参照エラーなし／再実行しても同結果（冪等）／想定外ポリシーがある状態では中止しDB無変更／rollbackでv43状態に戻る
2. **delete-account（Node上で実ファイルをトランスパイルし、Supabaseクライアントを模擬）** 8ケース全PASS
   - バケット無し → スキップして退会成功（従来どおり）
   - サーバーエラー・権限エラー・通信エラー（post-images／avatars）→ 失敗を返し、Authユーザーは削除しない
   - 同じテストを修正前のファイルで実行すると4ケースが「成功扱い」になることを確認
3. **SNS投稿削除（ヘッドレスChromium＋模擬Supabaseで実アプリの `snsSoftDeletePost` を実行）** 4ケース全PASS
   - 正常：写真削除→投稿更新の順、`{is_deleted:true,image_path:null}`

   - 投稿更新失敗：エラー表示（投稿は残る）
   - 写真なし投稿：従来どおり投稿更新のみ
4. **回帰（v51.4.4／v51.4.5）**：体験版 Lv.1 3/35、「365日中○日目」非表示、体験版プロフィール、日英表示、会話ログのユーザー分離10項目、ページエラー0件 — すべてPASS
   - 運動記録後の家具数は記録した時刻（夜の記録で解放される家具）により変わる。修正前のHEADでも同じ値になることを確認済み
